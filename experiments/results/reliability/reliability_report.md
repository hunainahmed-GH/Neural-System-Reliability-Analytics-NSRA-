## 1. Reliability Engine implementation status

**Implemented and unit-tested.** `src/reliability.py` provides:

- `find_contiguous_segments(binary_sequence)` - contiguous `(start, end)` runs (end inclusive); empty input returns `[]`.
- `ReliabilityEngine(y_true, y_pred).evaluate()` - true / detected / missed segment counts, detection coverage, per-segment detection delay, predicted segments, false-alarm segments and `false_alarm_segment_rate`.

Detection logic: a predicted segment detects a true segment if they overlap; delay = first overlapping predicted sample - true start; a true segment with no overlapping predicted segment is missed; a predicted segment that overlaps no true segment is a false-alarm segment. Undefined ratios (zero denominator) are reported as `None`/n/a.

Tests: `tests/test_reliability.py` (segment extraction, perfect detection, delay, missed segment, false-alarm segment, no-anomaly, no-prediction, length mismatch, plus a few extra edge cases).

## 4. Event-level false-alarm segment-rate definition

```
false_alarm_segment_rate = false_alarm_segments / predicted_segments
```

- `predicted_segments`: contiguous runs of predicted anomalies.
- `false_alarm_segments`: predicted segments that overlap **no** true anomaly segment.
- This is an **event-level segment proportion**. It is **not** the sample-level false positive rate (FP / (FP + TN)), which is what the `false_alarm_rate` field in the existing `metrics.json` files reports. The two measure different things and must not be compared or substituted.
- If there are no predicted segments the rate is undefined and reported as n/a.
